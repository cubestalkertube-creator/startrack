# Нативный клиент Startrack

Rust + gtk-rs (GTK 4), Tokio, reqwest, WebSocket и нативный LiveKit/WebRTC. В активном клиенте нет TypeScript, JavaScript, Node.js, Tauri, CEF или WebView. Сервер остаётся прежним.

## Windows

Нужны Rust MSVC и Visual Studio Build Tools с C++. Из корня репозитория:

```powershell
./client/scripts/setup-gtk.ps1
./client/scripts/gtk-env.ps1 -Run
./client/scripts/build.ps1 -Release -Package
```

`setup-gtk.ps1` скачивает GTK из wingtk/gvsbuild в `.cache/gtk/sdk`, не меняя системные переменные. Для своего SDK задайте `STARTRACK_GTK_DIR`. `gtk-env.ps1` меняет окружение только текущего процесса.

Переносимая сборка: `client/dist/Startrack_0.1.31_native_windows_x64.zip`. Распакуйте весь архив в одну папку и запустите `startrack.exe`. DLL и папки `share`, `etc`, `lib` должны оставаться рядом с программой. WebView2 не нужен.

## Linux

Нужны GTK 4.8+, Rust и компилятор C/C++. Например, Debian 12+ или Ubuntu 24.04+:

```sh
sudo apt install build-essential pkg-config libgtk-4-dev libdbus-1-dev libasound2-dev libpulse-dev libpipewire-0.3-dev libxcb1-dev libxrandr-dev libxfixes-dev libgbm-dev libva-dev libdrm-dev
sh client/scripts/linux-local.sh --run
```

Бинарник: `client/target/release/startrack`. GTK берётся из дистрибутива. В Wayland захват экрана требует работающего desktop portal и его разрешения.

## Первый этап переноса

- Вход и регистрация, друзья и запросы дружбы, личные и групповые сообщения.
- История с пагинацией, непрочитанные сообщения, переподключение WebSocket.
- Профили, статусы, аватарки и баннеры, загрузка и скачивание файлов до 500 МБ.
- Нативные голосовые комнаты LiveKit, микрофон, отключение звука, аудиоустройства, показ экрана или окна и приём видео.
- Контекстные меню сообщений, бесед, участников и демонстраций: правая кнопка или Shift+F10. Удалять можно только собственные обычные сообщения, с подтверждением.
- Эмодзи, отправка избранных GIF, текстовые чаты с Верити.
- Звуковая панель в звонке: семь встроенных эффектов, звуки участников, поиск, избранное, локальное прослушивание, загрузка WAV/MP3/OGG с выбором фрагмента до 5,2 секунды, изменение и удаление своих звуков. Команды совместимы с прежними клиентами LiveKit.
- Звуки сообщений, подключения и отключения участников, микрофона, отключения звука и показа экрана. Отдельные переключатели и громкость в «Настройки → Звуки», выбор динамиков для интерфейса и панели. Входящий звонок использует мелодию из админки сервера (первые 30 секунд), при её отсутствии — встроенную. «Не беспокоить» отключает звук входящих звонков и сообщений.
- Анимированные GIF в сообщениях, аватарках, баннерах и избранном. Декодирование идёт в фоне; анимацию можно отключить в настройках. Для GIF, превышающих 300 кадров или 32 МБ декодированных кадров, показывается первый кадр; исходный файл передаётся целиком.

- Обрезка аватарок (1:1, 512×512) и баннеров (3:1, 1200×400): перемещение, масштаб, загрузка оригинала. GIF обрезаются покадрово с сохранением задержек и повторов; для обрезки допускается до 300 кадров. Обработка идёт в фоне.
- Трей с открытием окна и полным выходом. По умолчанию крестик скрывает окно, сообщения и звонки продолжаются. Если служба трея недоступна, окно закрывается обычным образом. Автозапуск включается вручную в «Настройки → Приложение», запускает клиент с `--autostart`; Windows — отдельное значение StartrackNative в HKCU, Linux — отдельный desktop-файл XDG.
- Инструменты Верити: папки, чтение/запись/редактирование файлов, команды, открытие программ и запуск кода. Режимы «Выключен», «С подтверждением» (по умолчанию) и «Без подтверждений»; полный доступ включается отдельным нативным подтверждением. В режиме с подтверждением своя папка `Документы/Verity` доступна без вопросов, остальные файлы и команды требуют разрешения. Ссылки и junction-папки проверяются по фактическому пути. «Остановить» отменяет очередь действий и прерывает выполняемую команду; уже открытые отдельные программы остаются запущенными.
- Системный звук включается отдельно в окне выбора демонстрации, по умолчанию выключен. На Windows используется WASAPI process loopback с исключением Startrack: нужен Windows 11 / Windows 10 build 20348+. На Linux нужен PulseAudio или PipeWire-Pulse с `@DEFAULT_MONITOR@`: захватываются все звуки выхода, включая звонок; для изоляции нужен отдельный аудиовыход. Если звук недоступен, экран показывается без него с сообщением об ошибке. При остановке демонстрации аудиодорожка снимается отдельно от микрофона.
- Проверка нативных обновлений при запуске и каждые 6 часов, ручная проверка/скачивание/установка в настройках. Обновления проверяются прежним ключом подписи Startrack, установка с перезапуском запускается только пользователем и блокируется во время звонка или работы Верити. Windows-архив распаковывается в соседнюю временную папку, старая папка сохраняется как `.startrack-backup-*`; на Linux сохраняется предыдущий бинарник. Старый NSIS-канал `latest.json` не используется.

Следующий этап по договорённости: Android и встроенные YouTube/Spotify. Сервер и установленные старые клиенты не изменяются. Linux-сборка настроена в CI, локально на Windows не проверена. Физические аудиоустройства и сквозная работа Верити с внешней нейросетью требуют ручной проверки; автоматические тесты используют временные файлы и синтетическое аудио. Нативный канал обновлений начнёт предлагать версии после публикации подписанных файлов и `native-latest.json`. Эта работа сама релиз не публикует.

Настройки: каталог `ProjectDirs(app, startrack, Startrack)`, файл `native.json`. Пароль не сохраняется; токен хранится в системном хранилище учётных данных. Выход из аккаунта удаляет токен, закрытие окна сохраняет сессию.

## Проверки

На Windows сначала выполните `. ./client/scripts/gtk-env.ps1`.

```sh
cargo fmt --manifest-path client/Cargo.toml --check
cargo test --manifest-path client/Cargo.toml --lib
# На Linux для скрытой проверки GTK требуется дисплей, например xvfb-run -a cargo test …
# Нужен Node.js 24 и npm ci в server/
cargo test --manifest-path client/Cargo.toml --test api_contract
# STARTRACK_LIVEKIT_BIN — путь к официальному livekit-server
cargo test --manifest-path client/Cargo.toml --test api_contract native_media_round_trip -- --ignored
```

Тесты API создают временную БД и тестовые аккаунты на loopback-интерфейсе, проверяют также загрузку звуков и права редактирования. Медиатест передаёт синтетический звук, чёрные видеокадры и команды звуковой панели локально, без микрофона и захвата рабочего стола. Проверка GTK создаёт скрытые виджеты, не открывая окна и аудиоустройства. `STARTRACK_DEMO=1` открывает автономные тестовые данные только в debug-сборке.

`src/style.css` сохранён с существующими пользовательскими правками. Нативная тема — `src/native.css`.

## Подготовка обновлений без публикации

```powershell
./client/scripts/build.ps1 -Release -Package
./client/scripts/prepare-update.ps1 -NotesFile client/notes-0.1.31.md
# Опционально добавить собранный в Linux бинарник:
# ./client/scripts/prepare-update.ps1 -LinuxBinary path/to/startrack -WindowsArchive client/dist/Startrack_0.1.31_native_windows_x64.zip
```

Скрипт использует отдельную Rust-утилиту `startrack-sign-update` (фича `release-tools`, в обычный архив не входит), прежний ключ `~/.tauri/startrack-updater.key` либо `TAURI_SIGNING_PRIVATE_KEY` и пароль `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Секретный ключ не копируется в сборку; подпись проверяется встроенным публичным ключом до записи манифеста. Результат: `client/dist/native-update/` с архивом/бинарником, `.sig` и `native-latest.json`. Их можно выложить в GitHub-релиз `v<версия>`; скрипт ничего не публикует. Для отката Windows закройте Startrack и верните резервной папке исходное имя. На Linux замените бинарник сохранённым `startrack-<версия>.backup`.
